## 1. 边界与观测特征

内部边缘集合只包含ROI不与原图边界重合的边缘。对局部框原图坐标(x1,y1,x2,y2)，四个距离分别为x1−ROI_x1、y1−ROI_y1、ROI_x2−x2、ROI_y2−y2，仅在对应边缘为内部边缘时有效。d取有效距离最小值；输出框已经按原S2裁到ROI，d非负。没有内部边缘时设置boundary_available=0、d/r输入占位0，禁止把“无边界”误当d=0的高风险。

s=sqrt((x2−x1)(y2−y1))，r=d/(s+ε)，ε候选固定1e-6px；连续特征用log1p/训练拟合集标准化控制极值。宽/高均须保留：sqrt(wh)只是等效尺度，不等于垂直于最近边缘的真实尺寸。细长行人与近方形车辆可能有同样等效尺度但不同截断风险。第一轮保留log(w),log(h),log(w/h)及最近边缘方向one-hot，不额外再发明新模块。

全局特征：同类max IoU g、该max IoU对应s_g；任意类别max IoU、其置信度、类别是否一致。不存在相交的同类全局框时g/s_g=0且global_support_available=0。g=0不触发硬删除，训练监督必须包含可靠、全局漏检的局部框。类别c使用10维one-hot，不当连续整数距离。

跨ROI特征至少拆成三个量，不能只用单一a：

- observation_available：是否存在另一冻结ROI，完整覆盖本框并满足相同内部8px有效观察区；原图边缘豁免。这是几何观测机会，不是该ROI真的检出了GT。
- cross_support_iou、cross_support_score：仅来自这些有效其他ROI的同类预测，最大IoU和对应置信度；无候选时为0。
- observed_without_support：有有效其他ROI覆盖，但没有满足预注册支持IoU阈值的同类候选。它只是较弱的否定证据，绝不能硬删除；无有效其他ROI时此标志为0。

同一ROI的多标签拷贝不构成独立观测，所有证据以不同roi_id判定；重叠裁剪也不是独立传感器，不能把置信度简单相乘当独立概率。支持阈值候选.5，最终必须在训练侧dev锁定，不接触548验证GT。

## 2. 标签：把正确性、重复和定位改善分开

训练侧原始RGB上冻结M0/A1推理，ROI仍由原S2规则产生。验证侧只读取已冻结935个ROI。标签只用于离线训练，推理输入仅预测与几何。

建议在τ=.50,.55,…,.95构造：

1. 用全局final max500集合对正GT做类别感知、稳定置信度排序的一对一匹配，记录每个阈值下哪些GT已被全局检出。
2. 局部候选i独立找同类最大IoU正GT j*（重叠并列按固定GT ID）。valid_iτ=1[IoU(i,j*)≥τ]。该标签表示框对目标的几何/类别有效性，不是去重之后的唯一TP资格。
3. gain_iτ=valid_iτ ×1[j*未被全局在τ下匹配]。因此高IoU定位恢复也可产生gain，而不仅是IoU.5下新增目标。
4. 软标签y_valid=meanτ(valid_iτ)，y_gain=meanτ(gain_iτ)。所有ignore IoA≥.5候选屏蔽loss；这个训练ignore口径须写入配置，最终主AP仍沿用既有无额外过滤的Ultralytics口径，不能暗中换评价协议。

同一GT的可靠重复框应valid=1、gain=0，不能仅因“非新增”被标成无效目标。多个局部框覆盖同一遗漏GT会同时有正gain，所以该标签是潜在恢复能力，不是集合净贡献；最后必须固定统一NMS，并单列无益重复/挤出top500/替换全局TP的损害。普通双头标签不能保证融合后净收益，若没有优于普通重评分则应停止夸大其互补贡献。

损害诊断使用完整最终集合和原全局集合的一对一匹配差异，而不能把所有局部TP当新增TP。标签构造与最终融合需分别定义：这里不把验证GT加入任何候选保留操作。

## 3. 两头的概率语义与评分公式

用户候选式保留为待验证版本：s'=s·p_valid·[β+(1−β)p_gain]。β必须由训练侧dev固定。它只能降低原局部分数，可能挤压本来低分的真小目标；也可能在已有定位很差的全局框前压低更好的局部框，不能预设它优于B2。

必须区分两种gain输出，禁止混用：

- 若第二头输出联合事件Pr(valid且恢复)，理论上应≤p_valid；可用p_gain=p_valid×p_gain_given_valid约束。再把它代入用户公式会对validity重复衰减，需要单独对照。
- 建议主要版本的第二头定义为Pr(恢复 | 有效,z)，使用条件标签y_cond=y_gain/y_valid（y_valid>0时有效）并以y_valid作为loss权重。评分使用p_valid·[β+(1−β)p_gain_given_valid]，与联合头版本分列，不能把两个值都称作无条件新增概率。

多IoU软标签输出是阈值平均质量/恢复估计，不自动等于IoU.5事件的真实概率。需要dev上Brier/NLL、可靠性曲线、按尺寸/边界/可观测性分组校准；如另声称IoU.5概率，需针对该二元标签重新校准验证。温度缩放只使用dev，548验证集不用于选温度或β。

主模型候选：标准化特征→Linear32→SiLU→Linear16→SiLU→Linear2。L=BCE_soft(valid,y_valid)+λ·y_valid·BCE_soft(gain_cond,y_cond)，y_valid=0时第二项屏蔽；ignore候选两项均屏蔽。λ候选1，dev确认后锁定。soft label BCE为可训练损失；是否获得足够校准另行评估。

所有候选保留原框/类别，只校准局部分数；全局分数不改，统一class-aware NMS .7/final max500。原stage .001、local max10000、FP32映射保持；评分后过滤阈值的候选定义沿用既有.001并写入各组配置。不引入分类改写/框平均等额外机制。

## 4. 数据隔离与选择过程

质量器数据必须是官方train的原始图，不是中性填充过的local_dataset PNG。M0/A1均冻结，不重复30轮。ROI候选沿用S2，不用train GT决定实际推理选区；train GT仅构造质量标签。按原始源序列分组，所有同源图/ROI/候选留在同一组，先保存划分与hash，再生成标签。

较保守的第一轮：从未参与A1梯度更新的21个dev源序列再分quality-fit / early-stop / calibration三组，组比例候选60/20/20，seed42先锁分组；检测置信度/类别统计用于检查是否缺类，不根据548验证结果重分。数据较少时用分组嵌套交叉验证替代单次划分，不允许随机拆候选造成同图泄漏。

限制必须如实报告：这21组曾参与A1最佳epoch选择，全部train也曾用于M0训练，所以质量器分组隔离并不能撤销检测器层面的既有选择偏差。当前548验证集已被查看和讨论多次，也不是新的盲测集。独立泛化证明需要后续另获授权、事先锁定且从未参与任何开发的测试协议/数据；不能直接挪用test-dev标签调参或宣称已有干净测试。当前仅为开发研究证据。

质量器训练class imbalance很大；负例若抽样，需保存分层/逆概率权重，校准集尽量保留自然比例。统计标准化只fit组，早停只early-stop组，β和温度只calibration组；三个组用途明确，不能用同一个“dev”完成所有选择而不披露。

|C4−cross|C4去掉跨ROI观测特征，其他不变|观测证据是否有效|
|C4−global|C4去掉全局特征，其他不变|完整条件下的全局互补作用|

所有MLP用统一完整特征维度和同样双头/隐藏层；禁用组维度置零并采用同一训练标准化接口，以维持参数数目，不用追加层造成容量不匹配。单valid对照的第二头不参与loss/评分，保持结构一致并报告有效训练参数/输出差别。C4不可把r相对规则和原B2同时叠乘而不说明，否则会混入额外降分因素；主C4由网络使用r，替代B2评分，不隐式叠加。

严格机制归因依赖C4−boundary/−global/−cross：这些组保持双头均训练、同标签/损失/参数数目/选择过程，仅屏蔽指定特征。C2的单任务和C4的双任务监督不同，因此C4胜过C2不足以单独证明边界/互补特征作用。C4−gain可以用同一已训练C4权重关闭gain评分项作推理消融；若要验证gain辅助监督本身，另用同样容量重新拟合关闭第二项loss的组，两个问题分开报告。

ρ候选{.25,.5,1,2}、β候选{.25,.5,.75,1}属于拟议训练侧开发网格，不是验证集搜索；真正实施前锁网格与主指标，若样本不足则减少选择自由度。β=1使gain不起作用，是重要负对照。至少质量器seed42/43/44，检测器不再训练；报告均值/离散和按图或源序列配对bootstrap的不确定性，不把一次最优数值当显著性。

## 6. 接受/否定机制的证据

报告主AP50/95、COCO-small、10类AP、固定原图尺寸Recall、新增TP/丢失全局TP/FP、边界Precision、以及无观测/有支持/有观测无支持三组。必须检查全局未检出的可靠局部框有没有因gain评分被压低；<8像素组不能只报总体APsmall替代。

模型应报告valid/gain两头在训练外开发组的校准误差及真实恢复质量，不只给最终AP。全局冲突类只能作为输入，目前不改预测类别，不能声称实现了语义纠错。已有全局GT高IoU匹配、但局部更好定位的样本需单列。

耗时先用已有验证raw cache分析计算复杂度；后续正式评价计时必须实际跑M0全局+A1局部+特征构造/跨ROI对照+MLP/校准+最终NMS，包含CPU/GPU传输，所有组同运行顺序随机/交替、多次pass。冻结935ROI不重新选择，查表计时口径与E3联合评估一致。不要把缓存重评分时间标成端到端FPS。
